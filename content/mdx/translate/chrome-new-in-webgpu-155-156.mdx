# WGSL fragment\_depth 확장

기하학적 렌더링이 많은 렌더링 패스에서 early-Z 최적화는 개발자에게 매우 유용합니다. GPU가 비용이 많이 드는 fragment 셰이더를 실행하기 전에 숨겨진 픽셀을 버리도록 하여 성능을 크게 향상시킵니다. 래스터화된 깊이가 깊이 테스트를 통과하지 못하면, 셰이더에 다른 부작용이 없는 한 GPU는 fragment 셰이더를 완전히 건너뜁니다.

하드웨어가 이를 어떻게 처리하는지에 대해 더 자세히 알고 싶다면 MJP가 작성한 "[When Does Early-Z Have to be Disabled?](https://therealmjp.github.io/posts/to-earlyz-or-not-to-earlyz/#when-does-early-z-have-to-be-disabled)"를 참고하세요.

사용자 지정 깊이 조작은 유용하지만, fragment 셰이더에서 이를 수행하는 데는 숨겨진 비용이 따릅니다. `@builtin(frag_depth)`에 fragment 셰이더 내에서 쓰는 것은 일반적으로 드라이버가 전체 draw call에 대해 early-Z 최적화를 비활성화하도록 강제합니다. 이는 드라이버의 휴리스틱이 셰이더의 계산된 출력 깊이가 래스터라이저가 보간한 깊이와 일치한다고 보장할 수 없기 때문입니다.

이 성능 저하를 해결하기 위해 WGSL 확장 `fragment_depth`를 사용하면 `@builtin(frag_depth)`에 `less` 또는 `greater` 깊이 모드 이름을 지정하여 쓴 깊이가 보간된 깊이와 어떻게 비교되는지 명시적으로 나타낼 수 있으며, 이를 통해 GPU는 early-Z 최적화를 안전하게 적용할 수 있습니다.

이 언어 확장은 JavaScript에서 `navigator.gpu.wgslLanguageFeatures`를 사용하여 기능 감지할 수 있습니다. `requires fragment_depth;`를 WGSL 셰이더 코드 상단에 사용하여 이식성이 없을 수 있음을 알리는 것이 좋습니다. 다음 예시와 "[intent to ship](https://groups.google.com/a/chromium.org/g/blink-dev/c/sS8f4X1SEkk/m/v7fWPbr-DgAJ)"를 참조하세요.

```
if (!navigator.gpu.wgslLanguageFeatures.has("fragment_depth")) {
  throw new Error(`WGSL fragment depth is not available`);
}

const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();

const shaderModule = device.createShaderModule({ code: `
  requires fragment_depth;

  @fragment
  fn main() -> @builtin(frag_depth, less) f32 {
    // Explicitly states that the output fragment depth is less than early-Z depth,
    // allowing the GPU to safely preserve early-Z optimizations.
    return 0.0f;
  }`,
});

```

# 텍스처 압축 비정렬

"[`texture-compression-unaligned`](https://gpuweb.github.io/gpuweb/#dom-gpufeaturename-texture-compression-unaligned)" GPU 기능은 블록 크기의 정수 배수가 아닌 차원을 가진 압축 텍스처를 생성할 수 있도록 합니다 (BC, ETC2, ASTC 형식의 4x4 등). 이전에는 WebGPU에서 텍스처 크기가 이러한 블록 경계에 정렬되도록 엄격하게 요구했습니다. 이 기능은 텍스처를 패딩하거나 스케일링하여 블록 정렬에 맞출 필요성을 제거함으로써 스케일링 왜곡을 도입하지 않고 원래 압축 충실도를 유지합니다. "[intent to ship](https://groups.google.com/a/chromium.org/g/blink-dev/c/Hp-KNpz1iK4?e=48417069)"를 참조하세요.

다음 코드 스니펫은 어댑터가 텍스처 압축 비정렬을 지원하는지 확인하고, 지원하는 경우 이를 사용하여 장치를 요청합니다.

```
const adapter = await navigator.gpu.requestAdapter();
if (!adapter.features.has("texture-compression-unaligned")) {
  throw new Error("Texture compression unaligned support is not available");
}
// Explicitly request texture compression unaligned support.
const device = await adapter.requestDevice({
  requiredFeatures: ["texture-compression-unaligned"],
});

```

이 기능을 추진하고, 사양 및 CTS 작업을 이끈 spark.js의 외부 기여자 [Ignacio Castaño](https://www.ludicon.com/castano/blog/)님께 감사드립니다!

# srgb-linear 및 display-p3-linear 색 공간

"`srgb-linear`" 및 "`display-p3-linear`" 사전 정의된 색 공간이 추가됨에 따라 WebGPU 캔버스 컨텍스트는 이제 와이드 색 영역 디스플레이를 지원하기 위해 확장된 범위의 선형 색 공간으로 직접 렌더링할 수 있습니다. 이러한 색 공간은 픽셀 값과 물리적 휘도 간의 선형 관계를 유지합니다. 따라서 게임에서 물리적 광선 렌더링뿐만 아니라 안티 앨리어싱, 보간 및 데시메이션과 같은 공간 처리 작업에 이상적입니다. "[intent to ship](https://groups.google.com/a/chromium.org/g/blink-dev/c/MoKhf3DLhQM/m/41Asvc44CQAJ?e=48417069)" 및 "[Particles (HDR) sample PR #574](https://github.com/webgpu/webgpu-samples/pull/574)"를 참조하세요.

```
const adapter = await navigator.gpu.requestAdapter();
const device = await adapter.requestDevice();

const canvas = document.querySelector("canvas");
const context = canvas.getContext("webgpu");

context.configure({
  device,
  format: "rgba16float",
  colorSpace: "display-p3-linear",
});

```

# 추가 snorm10-10-10-2 정점 형식

"`snorm10-10-10-2`" 정점 형식은 네 개의 부호 있는 정규화 값을 보유하는 32비트 압축 형식입니다: 세 개의 10비트 컴포넌트 (`r, g, b`) 및 하나의 2비트 컴포넌트 (`a`). 이 형식을 사용하면 3D 법선 벡터와 추가 2비트 스칼라 또는 정렬 플래그와 같은 속성을 효율적으로 저장하면서 메모리 대역폭을 절약할 수 있습니다. "[spec PR 6491](https://github.com/gpuweb/gpuweb/pull/6491)"를 참조하세요.

# Linux NVIDIA용 f16 지원

선택적 "`shader-f16`" 기능은 WGSL에서 16비트 부동 소수점 값에 대한 지원을 제공합니다. 이제 최신 NVIDIA GPU 드라이버를 사용하는 Linux에서 지원됩니다. "[issue chromium:42251215](https://issues.chromium.org/42251215)"를 참조하세요.
