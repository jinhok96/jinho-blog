Anthropic은 AI 코드 생성 및 검토의 증가로 인해 CI 시스템에 상당한 부하가 발생하고 있습니다. 엔지니어당 코드 배포량이 8배 증가하고 Claude가 코드의 80%를 작성하며 PR 검토에도 참여하면서, 테스트 수 역시 10배 증가하여 CI 작업량이 6개월 만에 25배 급증했습니다.

-   **초기 해결책의 한계:** 처음에는 더 큰 머신을 사용하고, 프로세스를 병렬화하며, 서비스를 재시작하는 등의 단기적인 해결책을 시도했지만, 급격한 부하 증가에 빠르게 한계에 도달했습니다.
-   **재설계를 통한 확장성 확보:** 결국 기존 아키텍처를 전면 재설계하여 인메모리 데이터 스토어를 도입했습니다. 이를 통해 단일 프로세스의 상태 관리 부담을 줄이고, 리스너 워커가 어떤 결과든 처리 후 즉시 이동할 수 있도록 만들어 수평적 확장이 가능해졌습니다.
-   **AI 시대의 CI 확장 전략:** AI의 기하급수적인 코드 생성 능력을 고려하여, 초기 설계 단계부터 현재 예상 규모의 10~20배를 고려해야 합니다. 상태 관리는 프로세스 외부에서 처리하고, 단일 인스턴스로 실행되는 중요 서비스는 지양하는 것이 중요합니다.
-   **자동화 및 모니터링 강화:** Claude Tag와 같은 AI 도구를 활용하여 CI 시스템의 문제를 조기에 감지하고 점진적으로 개선하며, 입출력 CI 작업 수를 일치시켜 시스템 안정성을 유지하는 것이 필수적입니다.
