Claude Platform에서 여러 서브 에이전트를 포함하는 에이전트를 구축할 때, 메인 에이전트 루프에 통합하는 것이 더 나은 선택이 될 수 있습니다. Claude의 마이그레이션 킷을 사용하면 패턴을 식별하고 대안을 평가하며 최적의 접근 방식을 검증하는 안내 워크플로우를 따를 수 있습니다.

-   **단일 에이전트 루프의 이점**: 서브 에이전트 대신 메인 에이전트 루프에 기능을 통합하면 종종 품질, 비용 및 지연 시간 측면에서 이점을 얻을 수 있습니다. 복잡한 에이전트 구조는 컨텍스트 관리, 에이전트 난립, 일관성 없는 지침, 평가의 비효율성 및 높은 지연 시간과 같은 문제를 야기할 수 있습니다.
-   **점진적 공개 활용**: 컨텍스트와 도구를 점진적으로 공개하는 단일 에이전트 루프 설계는 공유 컨텍스트를 통해 더 나은 응답을 생성하고, 컨텍스트 번잡함을 방지하며, 최신 모델의 향상된 기능을 활용할 수 있습니다.
-   **서브 에이전트 통합 방법**: 서브 에이전트를 메인 에이전트 루프에 통합하는 과정은 각 서브 에이전트를 하나의 스킬과 API 호출로 구성된 도구로 전환하는 것을 포함합니다. 점진적 통합을 위해 먼저 공동의 엔드투엔드 평가 세트를 구축하고, 가장 사용 빈도가 높은 서브 에이전트부터 병합하거나 도구로 호출하는 방식을 고려할 수 있습니다.
-   **여러 팀의 기여**: 단일 에이전트 구조에서 각 팀은 자체적인 스킬과 도구를 관리하고, 중앙 팀이 시스템 프롬프트와 최종 품질을 총괄합니다. 스킬은 에이전트가 팀의 업무 방식을 이해해야 할 때, 도구는 특정 작업을 수행하거나 실시간 데이터를 읽어야 할 때 유용합니다.
-   **통합 가속화 도구**: Claude API는 평가 생성, 프롬프트 감사, 반복적인 앱 개선, 비용 최적화 등 서브 에이전트 통합 작업을 지원하는 다양한 스킬을 제공합니다.
