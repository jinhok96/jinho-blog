LLM 에이전트 개발 성공의 핵심은 복잡한 프레임워크가 아닌, 단순하고 조합 가능한 패턴을 활용하는 데 있습니다. 에이전트는 LLM이 도구를 활용하여 동적으로 작업을 수행하는 시스템입니다.

-   **에이전트 시스템의 종류**: '워크플로우'는 미리 정의된 코드로 LLM과 도구를 오케스트레이션하며, '에이전트'는 LLM이 자체 프로세스와 도구 사용을 동적으로 지시합니다.
-   **적절한 사용 시점**: 에이전트 시스템은 지연 시간과 비용을 증가시키는 대신 작업 성능을 향상시키므로, 이 트레이드오프가 합리적인지 고려해야 합니다. 복잡성이 필요할 경우, 워크플로우는 예측 가능성을, 에이전트는 유연성을 제공합니다.
-   **프레임워크 활용**: Claude Agent SDK, Strands Agents SDK, Rivet, Vellum과 같은 프레임워크는 초기 개발을 단순화하지만, 추상화 계층이 많아 디버깅이 어려울 수 있습니다. LLM API를 직접 사용하는 것부터 시작하고, 프레임워크 사용 시 내부 코드를 이해하는 것이 중요합니다.
-   **핵심 구축 블록**: 증강된 LLM(검색, 도구, 메모리 활용)은 에이전트 시스템의 기본입니다. Model Context Protocol을 통해 타사 도구와의 통합이 용이합니다.
-   **워크플로우 패턴**: 프롬프트 체이닝, 라우팅, 병렬화, 오케스트레이터-워커, 평가자-최적화자 등의 워크플로우 패턴은 특정 시나리오에 맞게 LLM 기능을 활용하는 데 유용합니다.
-   **에이전트 설계 원칙**: 단순성 유지, 계획 단계의 투명성 확보, 철저한 도구 문서화 및 테스트를 통한 에이전트-컴퓨터 인터페이스(ACI) 구축에 중점을 두어야 합니다.
