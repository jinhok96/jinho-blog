Claude Docs 팀은 출시 3주 전, 단일 노드에서 수천 명의 내부 사용자가 테스트하는 개념 증명 단계에서 시작했습니다. 그러나 야심 찬 출시 목표를 향해 나아가며, 수십억 건의 요청 속에서 단 60건의 서버 오류만을 기록하고 롤백 없이 성공적으로 출시를 완료했습니다. 이는 약 50개의 메모리 최적화 파드만으로 달성되었습니다.

이러한 성공의 핵심에는 두 가지 결정이 있었습니다.

-   **출시 규모에서의 카오스 루프 운영:** 스테이징 환경에 테스트 하네스를 구축하여 2주 동안 Claude가 서비스를 지속적으로 테스트하고 오류를 수정하도록 했습니다. 이를 통해 인프라의 모든 부분을 부하 테스트하고 문제점을 해결했습니다.
-   **Claude 가독성 향상:** Claude가 효과적으로 문제를 해결하기 위해서는 정확한 텔레메트리 데이터가 필수적이었습니다. 이에 따라 가비지 컬렉션과 같이 예측하기 어려운 런타임 사용을 피하고, Claude가 문제의 원인을 쉽게 추적할 수 있도록 기술 선택에 신중을 기했습니다.

이 모든 것이 가능했던 이유는 최근 Claude의 향상된 성능 덕분이었습니다. 최신 모델은 수 주간의 장기 실행에도 목표를 유지하며 이러한 복잡한 작업을 수행할 수 있습니다.

# 카오스 루프

수천 명의 내부 사용자와 단일 머신으로는 출시 시 서비스 생존력을 예측하기 어려웠습니다. 따라서 출시 2주 전, Claude가 스테이징 클러스터를 운영하며 하루에 백만 건 이상의 가상 문서를 생성하고 핵심 구성 요소를 의도적으로 실패하게 만들도록 했습니다. 이 과정에서 Claude는 시나리오 선택, 하네스 실행, 텔레메트리 분석, 수정 제안, 스테이징 배포 및 반복 작업을 수행했습니다.

테스트 하네스는 문서 생성과 같은 기능을 포화 상태로 만들었고, Claude는 Datadog MCP를 통해 텔레메트리를 분석하여 수정 옵션을 제안했습니다. 간단한 수정은 즉시 배포 및 재테스트가 이루어졌으며, 데이터베이스 쿼리 등의 모든 작업은 이름, 스캔 행 수, 반환 행 수 등 상세한 텔레메트리를 보고했습니다.

# Claude 가독성 향상

Claude가 높은 수준의 목표를 달성하도록 하려면, 코드에서 발생하는 모든 측정값이 우리가 작성한 코드로 추적 가능해야 했습니다. 이를 위해 두 가지 주요 조치를 취했습니다.

-   **진단 루프:** Claude는 모든 반복마다 텔레메트리를 읽고 누락된 부분을 추가했습니다. 예를 들어, 초기 단계에서 메모리 사용량이 높은 문서를 발견했을 때, Claude는 텔레메트리를 통해 문제의 원인이 내부 종속성 내의 별도 캐시에 있음을 파악하고 디버깅을 진행했습니다.
-   **가독성 있는 기술 선택:** Rust 언어를 사용하여 가비지 컬렉터의 영향을 피하고, 모든 메모리가 우리가 정의한 구조체에 저장되도록 했습니다. 또한, 의존성을 최소화하고 필요한 경우 코드를 자체적으로 관리(vendoring)하여 Claude가 모든 것을 측정하고 추적할 수 있도록 했습니다.

# 출시 주간

출시 당시 Claude Docs 서비스는 안정적으로 운영되었습니다. 첫 백만 건의 문서는 약 30시간 만에 생성되었으며, 9월 22일까지 460만 건을 넘어섰습니다. 9월 한 달간 629번의 배포가 이루어졌지만 롤백은 단 한 번도 없었습니다. 놀랍게도, 스테이징에서 연습했던 10가지 시나리오 중 7가지가 실제 프로덕션에서 발생했으며, Claude는 이미 런타임 플래그 뒤에 수정 사항을 준비해 두어 즉시 적용할 수 있었습니다.

# 현재 왜 작동하는가

이러한 방식은 최근 Claude 모델의 성능 향상 덕분에 가능해졌습니다. 이전 모델들은 장기 실행 시 목표를 잊어버리는 경향이 있었으나, 최신 모델은 수많은 컴팩션을 거치면서도 모든 불변 조건을 유지하며 장기적인 작업을 성공적으로 수행합니다. Vercel 또한 유사한 에이전트 루프를 사용하여 Turborepo 성능을 96%까지 향상시킨 바 있습니다.

# 비용

2026년 11월 기준 Claude Fable 5.2 API 요금으로, 8월 말부터 출시일까지 약 125,000 달러의 추론 비용이 발생했습니다. 이러한 규모의 작업은 과거에는 엔지니어 팀이 6개월 이상 소요될 것으로 예상되었습니다. 초기 설정 및 실험 과정에서 비용이 더 발생했으며, 최적화된 프로세스로는 비용을 절반으로 줄일 수 있을 것으로 예상됩니다.

# 시도해보기

이러한 접근 방식은 훨씬 작은 규모의 서비스에도 적용 가능하며, 비용도 상당히 절감됩니다. Kubernetes 노드와 PostgreSQL 인스턴스를 사용하는 일반적인 소규모 팀 환경을 기준으로, 2주간의 이러한 작업은 약 3,000달러에서 10,000달러 사이의 비용이 소요될 것으로 추정됩니다.

시작하기 위해서는 Claude에게 텔레메트리 접근 권한을 부여하고, 실제 트래픽의 10배에 달하는 부하를 발생시키는 테스트 스크립트를 작성해야 합니다. 또한, Claude가 측정하기 쉬운 기술 스택(Rust 및 최소 의존성)을 선택하고, 핵심 기술 불변 조건을 명확히 정의해야 합니다. 되돌리기 어려운 변경 사항에 대해서는 Claude가 사용자에게 옵션과 명확한 권장 사항을 제공하도록 설정해야 합니다.
